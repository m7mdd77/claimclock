ClaimClock: Where Things Happen

A local deadline and readiness board. This is a reference route through the actual implementation, not a claim that a learner completed an interactive code tour.

Edit form→Validate entry→Save in browser→Render status

Follow One Action

  1. app.mjs, search onsubmit: collects a deadline, checklist and receipt separately.
  2. domain.mjs, search validate and status: checks inputs and derives readiness. All requirements completed is not a submission receipt.
  3. app.mjs, search save and render: persists before updating the screen. Synthetic entries stay excluded from totals.

To Change This, Start Here

  • Deadline/status rules: domain.mjs and domain.test.mjs.
  • Fields and wording: index.html; visual layout: style.css.
  • Export format: exportEntries and importEntries in domain.mjs.

A Practice to Reuse

Make progress and confirmed outcomes separate states. The test named “a completed checklist is not a submission” protects that distinction; a browser check verified that completing a requirement changes the row to ready, not submitted.

Run Again

In this project's folder run npm test, then npm start. Open ClaimClock locally. Export a backup before clearing browser storage.
